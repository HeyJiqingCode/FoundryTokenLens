# FoundryTokenLens 使用手册

## 1. 概述

FoundryTokenLens 是一个自托管的 Microsoft Foundry 用量看板。Foundry 资源会把诊断日志写入 Azure Blob Storage，平台读取这些日志，把每次模型调用的用量记录（Usage）和请求记录（RequestResponse）合并成一条请求，得到它的 Token、费用、状态码、耗时和来源 IP，再汇总成可以按时间、模型和资源查看的报表。

### 1.1. 主要功能

平台提供概览、用量分析和请求明细三类页面，其中用量分析分为成本、Token 与缓存、调用分布、性能与可靠性四个视角：

- **概览**：汇总所选时间范围内的总费用、调用次数、Token 用量、缓存命中率和错误率，并与上一个等长时段对比；同时展示费用与用量趋势、错误与耗时、各模型的费用占比，以及费用最高的请求。
- **成本**：按计费类型、模型或资源拆分费用，计算缓存带来的节省，按本月至今的日均费用预测月底总额，并给出单次费用分布和费用最高的请求。
- **Token 与缓存**：统计输入、缓存读取、缓存写入和输出四类 Token，按模型或资源跟踪缓存命中率，列出命中率最低的请求，并给出上下文、输入和输出的分布。
- **调用分布**：从时间、星期 × 小时和来源 IP 三个维度分析调用分布，并按模型或资源汇总调用次数、费用、Token、错误率和耗时。
- **性能与可靠性**：统计成功请求的耗时、首 Token 和末 Token 的 P95 趋势与分布、生成速度分布，以及输入长度与首 Token 时间的关系；同时分析错误、限流和响应状态码，并列出最慢的请求。
- **请求明细**：逐条查看合并后的请求，可按条件筛选、查看单次请求的完整详情，并导出 CSV。
- **筛选与下钻**：所有报表共用模型、资源、状态、上下文、来源 IP、时间范围、粒度和时区筛选，筛选条件保存在链接中；图表可按模型或资源拆分，悬停可查看各资源下的模型，在时间图上拖选一段即可缩小时间范围。

### 1.2. 工作方式

- **只读日志**：通过连接字符串或托管身份读取 Blob 中的日志，不修改、不删除 Blob 里的文件。
- **增量导入**：定时任务按白天和夜晚各自的间隔扫描，只读取新增或变化的日志；复核任务按设定的天数重新核对一遍 Blob 中的文件，第一次执行时核对全部文件。
- **手工维护单价**：价格按生效时段管理，区分短上下文和长上下文，可以从 Azure 零售价格预填。每次请求按它开始时生效的价格计费，日志或价格变化后自动重算。
- **单机部署**：所有数据保存在一个 SQLite 数据库里，一个 Node.js 进程同时提供界面和接口；支持本地管理员、只读用户和 Microsoft Entra 登录，界面有中文和英文。

## 2. 部署

**1、创建 Docker 容器**

```bash
docker run -d --name foundrytokenlens --init --restart unless-stopped \
	-p 127.0.0.1:8080:8080 \
	-v ftl-data:/app/data \
	ghcr.io/heyjiqingcode/foundrytokenlens:0.0.4
```

> 镜像以 UID 1000 运行，数据库和密钥保存在 `/app/data`。

**2、初始化设置**

首次打开平台时，在浏览器中创建第一个管理员，这次访问用的地址会被记为平台访问地址。完成初始化之前，任何能访问到平台的人都可以抢先创建管理员，所以部署后要马上完成初始化。\
![](../img/docs/20261013132848.png)

**3、参数设置**

| 变量               | 说明                                                                                                                                   | 默认值                              |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| `FTL_PUBLIC_URL`   | 平台访问地址。会覆盖初始化时记录的地址和单点登录设置中保存的地址；只有来自这个地址的请求才能登录或修改数据，Entra 回调地址也按它生成。 | 初始化时记录的地址                  |
| `FTL_SECRET_KEY`   | Base64 编码的 32 字节主密钥，用于加密凭据和为登录会话签名。丢失或更换后，已保存的凭据无法再解密，所有登录会话都会失效。                | 自动生成并保存在 `data/.secret-key` |
| `FTL_HOST`         | 监听地址                                                                                                                               | `0.0.0.0`                           |
| `FTL_PORT`         | 监听端口                                                                                                                               | `8080`                              |
| `FTL_WEB_DIR`      | 构建后的界面文件所在目录                                                                                                               | `dist/web`                          |
| `FTL_DEV_API_PORT` | 开发服务器所代理的后端 API 端口                                                                                                        | `8081`                              |

## 3. 数据管理

平台依托 Foundry 资源的诊断日志进行各项数据的展示，同时，为了节省成本，仅支持对 Archive 到 Blob 中的诊断日志进行提取。另外，Foundry 资源提供多种诊断日志，平台仅读取其中两类日志：

| 诊断日志类别               | Blob 容器                               | 提供的数据                           |
| -------------------------- | --------------------------------------- | ------------------------------------ |
| Azure OpenAI Request Usage | `insights-logs-azureopenairequestusage` | Token 用量、首 Token 和末 Token 时间 |
| Request and Response Logs  | `insights-logs-requestresponse`         | 状态码、耗时、来源 IP、请求开始时间  |

> 两类日志都开启，数据才完整：只有用量日志时，看不到状态码和耗时；只有请求日志时，没有 Token，也就算不出费用。

### 3.1. 开启诊断日志

**1、添加诊断设置**

在 Azure Portal 打开 Foundry 资源，左侧菜单选择 Monitoring / Diagnostic settings，点击 + Add diagnostic setting。\
<img src="../img/docs/20261013141304.png" width="700">

**2、填写相关信息**

填入设置名称，在 Logs 中勾选 Azure OpenAI Request Usage 和 Request and Response Logs，在 Destination details 中勾选 Archive to a storage account，选择订阅和存储账户。\
![](../img/docs/20261013141828.png)

> 每个 Foundry 资源都要单独添加诊断设置，如果有多个资源，建议写到同一个存储账户，平台会一并读取。\
> 按 Azure 的说明，初次设置日志最长可能要约 2 小时才会写入。写入后，存储账户的 **Containers** 中会出现上表中的两个容器，后续请求时间和日志写入 Blob 时间差约为 1 分钟。

### 3.2. 添加数据源

平台支持两种方式读取存储账户：

| 方式              | 适用场景                                                 | 需要准备                                           |
| ----------------- | -------------------------------------------------------- | -------------------------------------------------- |
| Connection string | 平台部署在任何地方                                       | 存储账户的连接字符串                               |
| Managed identity  | 平台部署在 Azure 上（例如 Container Apps），不想保存密钥 | Storage Account 名称，以及为托管身份分配的读取权限 |

**1、方式 1：使用 Connection string**

打开存储账户，左侧菜单选择 Security + networking / Access keys，点击 Show keys，复制 key1 下的 Connection string。\
![](../img/docs/20261013143017.png)

**2、方式 2：使用 Managed identity**

1）为运行平台的 Azure 资源开启托管身份。\
以 Container Apps 为例：打开容器应用，选择 Settings / Identity，在 System assigned 下把 Status 切换为 On，点击 Save。如果使用用户分配的托管身份，记下它的 Client ID。\
![](../img/docs/20261013144120.png)

2）新建角色分配\
打开存储账户，选择 Access control (IAM) / + Add / Add role assignment。\
![](../img/docs/20261013143751.png)

3）分配角色\
角色选择 `Storage Blob Data Reader`，在 Members 中选择 Managed identity，点击 + Select members 选中上一步的身份，再点击 Review + assign。\
![](../img/docs/20261013144020.png)

![](../img/docs/20261013144329.png)

> 必须分配 `Storage Blob Data Reader`。Reader、Contributor 只有管理权限，没有读取 Blob 数据的权限。\
> 角色分配可能需要几分钟才生效。\
> 如果存储账户开了防火墙，要允许平台所在的网络访问。

**3、使用上述任一方式在平台中添加数据源**

1）进入 Settings / Data management，在 Data sources 卡片点击 Add data source。\
![](../img/docs/20261013144646.png)

2）选择 Authentication：

- Connection string：粘贴上一步复制的连接字符串。
- 若使用 Managed identity，则填写 Storage Account 名称，Client ID 留空表示使用系统分配身份，使用用户分配身份时填它的 Client ID。

![](../img/docs/20261013144743.png)

3）测试并保存\
点击 Test connection。连接成功后，Diagnostic logs 区域会标出两类日志是 Identified 还是 Not identified，至少识别到一类才能保存。\
![](../img/docs/20261013144834.png)

> 右上角的开关决定数据源是否启用，新建时随表单一起保存。

### 3.3. 管理数据源

数据源管理支持以下操作：

- **文件统计**：数据源卡片显示 Blob 中的文件数量和存储量，点击 Refresh file statistics 更新。
- **启用、禁用**：禁用后不再导入，报表中也不显示它的数据。
- **编辑**：已保存的连接字符串不会再显示；不重新填写就沿用原来的，输入新值则替换。
- **删除**：需要输入 Blob 名称确认。删除后不再导入或展示该数据源的数据，已处理的日志数据会保留，重新添加同一个 Blob 存储后可以继续使用。

![](../img/docs/20261013150106.png)

> 同一个请求如果同时出现在两个启用的数据源里，会在两个数据源中各算一次，导入时会在系统日志里记一条警告。

### 3.4. 添加定时任务

定时任务决定平台什么时候去数据源读取新日志，分两种：

| 任务类型 | 作用                                                                   | 默认规则                                  |
| -------- | ---------------------------------------------------------------------- | ----------------------------------------- |
| 日常任务 | 按日间、夜间两个时段各自的间隔扫描，只读取新增或变化的日志             | 日间 06:00–22:00 每 5 分钟，夜间每 1 小时 |
| 复核任务 | 每隔几天在指定整点重新核对一遍 Blob 中的文件；第一次执行时核对全部文件 | 每 1 天，06:00                            |

> 建议每个数据源各配一个日常任务和一个复核任务。

**1、新建任务**

1）在 Scheduled tasks 卡片点击 Add scheduled task。\
![](../img/docs/20261013151001.png)

2）填写 Task name，选择 Task type、Time zone 和 Linked data sources（可多选，支持搜索）。\
![](../img/docs/20261013151353.png)

3）设置执行规则

- 日常任务：在 Day 中设置 Start time、End time 和 Interval (minutes)，其余时间就是 Night，再在 Night 中设置 Interval (hours)。间隔必须能整除所在时段的时长。
- 复核任务：选择 Reconciliation hour 和 Frequency (days)，频率为 1–7 天。

![](../img/docs/20261013151550.png)

![](../img/docs/20261013151519.png)

> 同一个数据源只能关联一个启用的日常任务和一个启用的复核任务。

**2、立即扫描**

不想等下一次调度时，在 Scheduled tasks 卡片点击 Scan now，选择数据源后点击 Start scan。

**3、管理任务**

- **启用、禁用**：任务的开关单独生效。
- **删除**：停止该任务的自动调度，数据源和已导入的日志、用量、费用都保留。
- **重置历史任务信息**：停止当前任务并禁用全部定时任务，清空执行记录、执行次数、调度及复核进度。任务配置、数据源和已导入的数据保留。重新启用复核任务后，会再执行一次全量复核。

## 4. 单价设置

平台不会自动计价，每个模型的单价都要在 Settings / Unit prices 里维护。

> 未设置单价的模型，在报表、筛选和导出中都不显示。设置单价后，这个模型之前的调用会按当时生效的价格算出费用，并重新显示出来。

**1、模型列表**

导入日志后点击 Refresh models，日志里出现过的模型都会列出来。来自日志的 Model ID 不能修改。也可以点击 Add model，手动填写 Model ID 和 Display name。每个模型可以执行 Edit price、Price history 和 Delete model 操作。

![](../img/docs/20261013151946.png)

**2、编辑价格**

单价的单位是 **USD / 1M Tokens**，默认使用 Global Standard 价格。

1）点击 Edit price，至少填写一项单价。\
2）设置 Start time，需要时再设置 End time (optional)。\
3）文本模型如果按上下文长度区分价格，开启 Context tiers，填写 Input token threshold（例如 272000），再分别填写 Short context 和 Long context 的单价。

![](../img/docs/20261013152135.png)

**3、从 Azure 零售价格预填**

在编辑价格时点击 Get prices，平台会按日志中资源所在的区域查询 Azure 零售价格。选好价格后点击 Fill draft，核对无误再保存。查不到或计费项超出模板的模型，需要手动填写。

![](../img/docs/20261013152204.png)

**4、价格历史与调价**

价格调整时，在 Edit price 中点击 New version，填写新的 Start time，上一个版本会自动在这个时间结束。各版本的有效期不能重叠。每个版本标有生效中、待生效或已结束。每次请求按它开始时生效的价格计费；价格改动后，受影响的请求会自动重新计算。

![](../img/docs/20261013152257.png)

**5、删除模型**

Delete model 需要输入 Model ID 确认，会删除它的价格历史和已计算的费用，并从模型列表中移除。日志和用量保留，重新添加模型后可以再设置价格。

## 5. 身份认证

### 5.1. 本地用户

平台有两种角色：

| 角色     | 权限                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 管理员   | 查看全部报表，管理数据源、定时任务、单价、用户和平台设置               |
| 只读用户 | 查看报表和请求明细，设置中只能查看平台设置，不能修改，也看不到系统日志 |

**1、新增用户**

1）在 Users 卡片点击 Add user。\
2）填写 Email、Display name、Initial password（8–128 个字符）并在 Confirm password 中再次输入，选择 Role。\
3）点击 Create user。

![](../img/docs/20261013152512.png)

![](../img/docs/20261013152538.png)

**2、管理用户**

为防止失去管理入口，平台有这些限制：

> 初始本地管理员（初始化时创建的那个）不能删除，也不能更改角色。\
> 必须保留至少一个已启用的本地管理员。\
> 不能修改自己的角色，也不能停用或删除自己。

用户管理支持：

- 在用户列表里直接切换角色。
- Edit user 可以修改资料、重置密码、启用或停用账户。停用的用户无法登录。
- Delete user 需要输入该用户的邮箱确认，没有邮箱的用户输入显示名称。删除后账户及登录凭据被移除，现有会话立即失效；历史日志、用量和费用数据保留。

**3、个人账户**

点击左下角的用户区，打开 Account 可以修改个人资料和密码。修改邮箱需要验证当前密码；修改密码后，其他登录会话会失效。

![](../img/docs/20261013152705.png)

### 5.2. 单点登录

配置后，组织用户可以在登录页点击 Sign in with Microsoft，用 Microsoft Entra ID 账号登录平台。

**1、注册应用**

1）新建应用注册\
打开 Microsoft Entra ID / App registrations，点击 + New registration。\
![](../img/docs/20261013154310.png)

2）填写相关信息\
填写名称，Supported account types 选择 Multiple Entra ID tenants，Redirect URI 选择 Web，填写平台 Single sign-on 卡片中显示的 Redirect URI。\
![](../img/docs/20261013154704.png)

3）记录相关信息\
在 Overview 页记下 Application (client) ID 和 Directory (tenant) ID。\
![](../img/docs/20261013154850.png)

4）生成 Client secret\
选择 Certificates & secrets / Client secrets / + New client secret，填写说明、选择有效期后点击 Add。\
![](../img/docs/20261013155055.png)

> 复制新密钥的 Value（不是 Secret ID），离开页面后就看不到了。\
> Client secret 到期前要新建一个，并在平台中更新。\
> 平台只请求登录所需的基本资料（openid、profile、email）。如果组织不允许用户自行同意应用，需要租户管理员同意。

**2、在平台中配置**

1）进入 Settings / Authentication，在 Single sign-on 卡片中填写：

- Platform URL：用户访问平台的地址，可以点 Use current address。线上必须使用 HTTPS，HTTP 只用于 localhost 或 127.0.0.1。设置了 `FTL_PUBLIC_URL` 时由它决定，这里不能修改。
- Redirect URI：根据 Platform URL 自动生成，点击复制后填到应用注册的 Redirect URI。
- Tenant ID：允许登录的租户，多个用 `;` 分隔，最多 20 个。
- Client ID、Client secret：填写上一节记下的值。
- Make new users admins：只影响首次登录的 Entra 用户；关闭时，他们首次登录后是只读用户。

![](../img/docs/20261013155407.png)

2）打开 Enable Microsoft Entra ID sign-in (multitenant support)，点击 Save Entra settings。保存过一次之后，启用开关单独生效，不用再点保存。\
![](../img/docs/20261013155637.png)

> Entra 用户首次登录时会自动创建平台账户，出现在 Users 中。他们的密码和 MFA 由 Microsoft Entra ID 管理。\
> 要阻止某个 Entra 用户登录，请停用他的账户。删除只会移除平台账户，他下次登录时会重新创建。

![](../img/docs/20261013155515.png)

## 6. 平台设置

Settings / Platform settings 页有 System data 和 System logs 两张卡片。只读用户也能打开这一页，但只能查看。\
![](../img/docs/20261013155850.png)

### 6.1. 系统数据

| 项目        | 说明                           |
| ----------- | ------------------------------ |
| SQLite 容量 | 数据库文件的大小，含可复用空间 |
| 监控数据    | 已处理的诊断日志及其用量、费用 |
| 平台数据    | 账户、配置与任务进度           |
| 系统日志    | 平台操作记录                   |

Clear monitoring data 需要输入 `DELETE` 确认。清空时会停止正在运行的任务并禁用全部定时任务，删除已导入的日志及关联的用量、费用、导入断点和复核进度。用户、数据源、价格配置、任务配置和系统日志都保留，Azure Blob 中的原始文件不受影响；重新启用任务后可以再次导入。\
![](../img/docs/20261013160003.png)

### 6.2. 系统日志

系统日志只有管理员可以查看，记录三类事件：

- **任务**：定时扫描和手动扫描的过程与结果。
- **操作**：用户在平台上的新增、修改、删除操作。
- **系统**：平台启动等运行事件。

可以按 Category、Level（Info、Warning、Error）筛选，或在 Search logs 中搜索。每条日志显示事件、对象、操作者和详情。

**日志保存策略**

| 设置项                  | 说明                                                       |
| ----------------------- | ---------------------------------------------------------- |
| 系统日志容量上限（MiB） | 超过后清理最旧的日志                                       |
| 保留天数                | 超过天数的日志会被清理                                     |
| 记录事件类型            | 多选：定时扫描、手动扫描、新增、修改、删除；都不选则不记录 |
| 记录级别                | 多选：信息、警告、错误；都不选则不记录                     |

![](../img/docs/20261013160139.png)

> 容量或天数先达到哪个，就按哪个清理最旧的日志。事件类型和级别只影响之后的记录。

**清空系统日志**

清空历史扫描、操作和系统日志。正在运行的任务、执行次数、处理进度和监控数据保留。

## 7. 计算口径

**1、请求的合并**

- 平台按 `resourceId` 和 `correlationId` 把同一次调用的用量日志和请求日志合并成一条请求。
- Token 只取自用量日志，缺失时不估算。首 Token 和末 Token 时间也来自用量日志；状态码、耗时和来源 IP 来自请求日志。
- 没有请求日志的请求，状态显示为「状态未知」；同一请求的多条记录状态码不一致时，显示为「字段冲突」。
- 报表只统计启用的数据源。同一个请求出现在两个启用的数据源中时，会各算一次。

**2、请求时间**

请求按开始时间（请求日志中的请求时间）归入时段；没有请求日志时，按日志写入的时间。

**3、费用**

- 输入 Token 中已经包含缓存读取和缓存写入，计费时拆开计算：计费输入 = 输入 − 缓存读取 − 缓存写入。缓存数量缺失时按 0 计算。
- 费用 = Σ（各计费项数量 × 单价）÷ 1,000,000。
- 每次请求使用它开始时生效的价格版本。日志或价格变化后，费用自动重算。
- 价格开启了按上下文长度分档时，输入 Token 大于分界值按长上下文计费，否则按短上下文；没有分档的价格记为 Other。筛选里的「上下文」按这个结果划分。
- 还没有算出费用的模型，在报表、筛选和导出中都不显示。

**4、Token 与缓存**

- 缓存命中率 = 缓存读取 ÷ 输入，只统计有用量日志、且缓存读取不大于输入的请求。
- 缓存节省：缓存读取的 Token 按输入单价计算的费用，减去它们实际按缓存读取单价产生的费用。
- 缓存命中率最低请求：只看输入不少于 1,024 Token 的请求，分非 0% 和 0% 两组，各列 20 条。命中率相同时，未命中的输入 Token 多的排在前面。

**5、成功请求与性能**

- 成功请求：有请求日志、状态码已知且小于 400、没有字段冲突。
- 耗时、首 Token、末 Token 和生成速度只统计成功请求。
- 生成速度 = 输出 Token ÷（末 Token 时间 − 首 Token 时间），单位 Token/s；输出少于 100 Token 的请求不计算速度。
- P50 / P95：把数值从小到大排序，取第 ⌈n × 50%⌉ / ⌈n × 95%⌉ 个。
- 错误率 = 状态码 ≥ 400 的请求 ÷ 状态码已知的请求。

**6、对比与预测**

- 较上期：与紧挨着的上一个等长时段比较。例如当前看最近 14 天，上期就是再往前的 14 天。
- 本月费用预测：
  - 只看报表时区下的当前自然月，不受时间范围影响，但会跟随模型、资源等其他筛选。
  - 日均费用 = 本月至今费用 ÷ 已过天数（不足 1 天按 1 天计）；月底预测 = 本月至今费用 + 日均费用 × 剩余天数。
  - 上月总额是上一个自然月的总费用，作为对照。
